## TL;DR
Harrison Chase explains that building an agent requires balancing three core components—harness, model, and context—and advocates starting with general off-the-shelf harnesses before customizing via middleware as tasks move out-of-distribution.

## Anatomy of an Agent: Harness, Model, and Context
* **The Three Core Pillars:** According to LangChain, every agent consists of a harness, a model, and context; owning your intelligence requires owning all three parts.
    * **Model Flexibility:** Being able to switch between open weight and proprietary models avoids vendor lock-in and ensures you always use the best available model.
    * **Context Management:** Managing memory, semantic knowledge, and previous conversations helps personalize and guide the agent's behavior.
    * **Harness Orchestration:** The harness acts as the orchestrator, bringing dynamic and fixed context into the model's context window at the right point in time.
* **The Core Agent Loop:** At its simplest, an agent is an LLM running in a loop that calls tools, evaluates observations, and passes them back to the model.

## Customizing Harnesses with Middleware and Model Profiles
* **Using Middleware for Customization:** Developers can modify the base agent loop using small middleware constructs, hooks, and plugins without rewriting the core architecture.
    * **Enabled Capabilities:** Middleware allows harnesses to connect to sandboxes, file systems, sub-agents, memory, and summarization steps.
    * **Context Offloading:** Large tool calls can be wrapped and dumped to manage context length efficiently.
* **In-Distribution vs. Out-of-Distribution Tasks:** The more out-of-distribution a task is, the more customization your harness requires.
    * **Keeping In-Distribution Sub-Tasks Close to the Model:** Even on custom out-of-distribution tasks (like legal AI), foundational sub-tasks like file editing should mirror what the model was explicitly RL'd on.
    * **Model Profiles:** Deep Agents utilizes model profiles to dynamically switch between different file-edit implementations depending on whether an OpenAI or Anthropic model is active.

## Evals, Benchmarks, and Observability
* **Setting Private Evals:** Mirroring Satya's framing, organizations must create private evaluations to define what "good" looks like and build a continuous hill-climbing improvement loop.
* **Harbor as an Open-Source Standard:** Harbor has emerged as an industry-standard open-source eval runner (created by the makers of Terminal Bench 2) used to run data sets in sandboxed Dockerfile environments.
* **Comprehensive Benchmarking:** Benchmarks should track not just accuracy, but also latency and token cost across different agent harnesses, models, and reasoning efforts.
* **Observability and Trajectories:** Observability is critical for debugging why an LLM call failed—usually resulting from poor context accumulation rather than an inadequate model.
    * **Message Trajectories:** Agents run primarily on message trajectories (human inputs followed by underlying tool-call messages and responses).
    * **Debugging Views:** Platforms like LangSmith provide both user-friendly summarized views and deep trace views to inspect exact model inputs and outputs.

## The Data Flywheel and Automated Harness Engineering
* **Continuous Improvement Recipe:** Build an agent, collect traces, curate trace data, and run experiments to update any part of the agent (harness, model, or context).
* **Feedback Mechanisms:** Collecting high-quality feedback relies on clever UX design to capture implicit user signals, combined with fast, low-cost synthetic feedback from fine-tuned Small Language Models (SLMs) acting as judges.
* **LangSmith Engine:** LangChain built Engine—an internal background agent that sits on top of LangSmith traces, runs using a coding agent with a LangSmith CLI, and automatically generates issue boards, prompt updates, and harness code changes.
