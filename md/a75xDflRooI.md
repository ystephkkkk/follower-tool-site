**TL;DR:** Standard Chartered is leveraging OpenAI Daybreak to outpace attackers by shifting security from static code analysis to contextual vulnerability assessment across enterprise microservices, architectures, and trust boundaries. By embedding AI remediation directly into the development pipeline, the global bank is transforming security teams from blockers into enablers.

## The Defender's Window and Frontier AI at Enterprise Scale
- **Understanding Exploits over Vulnerabilities:** Reuben Athaide (**Standard Chartered**) noted that frontier models shorten the time to understand software and identify exploits, making it crucial for global financial institutions to understand exploitable paths faster than attackers.
  - Attackers focus on attack paths across systems, APIs, IDs, and trust boundaries rather than isolated repos and assets.
  - The goal is moving beyond generating a longer list of CVEs to identifying what is truly exploitable.
- **Early Adoption of OpenAI Daybreak:** Standard Chartered is among the first banks globally to evaluate OpenAI Daybreak to gain insights traditional security approaches miss.
  - Matt Weaver (**OpenAI**) highlighted Daybreak as a critical component of the upcoming defender ecosystem.

## The Power of Context in Code Security
- **Context Over Model Choice:** According to Reuben Athaide, having comprehensive context matters more than which specific model is selected.
- **Inputs Required for Deep Context:** To achieve actionable findings, Standard Chartered feeds additional data into the model alongside codebases, including:
  - Architecture diagrams and architecture deployment models.
  - Dependencies and connected services utilized across assets.
  - The original solution intent of the item being reviewed.
- **Uncovering Hidden Gaps:** Using Daybreak, the bank discovered areas and insights that traditional tooling entirely failed to pick up on.

## Cross-Functional Collaboration and Developer Trust
- **Collaborative Validation:** Reuben Athaide emphasized that simply showing demos to development teams is insufficient; findings must be validated against actual code, architecture deployments, and environments through cross-functional groups combining application security and development teams.
- **Shifting Left and Self-Service:** Security is being integrated earlier into the pipeline, creating virtual workspace areas in the development cycle where teams can test and verify exploitability safely.
- **Efficiency in Remediation:** Instead of adding unverified tasks to a developer backlog or acting as a restrictive gatekeeper, Standard Chartered uses frontier AI to help developers understand root causes and directly automate remediation.

## Foundation Readiness and Global Scale
- **Strengthening Core Foundations:** Reuben Athaide stressed that organizations must establish solid foundations before deploying AI, which will otherwise amplify existing flaws:
  - Reduce technical debt and technology complexities (such as minimizing the number of programming languages used).
  - Keep architectures up-to-date to provide necessary context.
  - Maintain solid identity and access control mechanisms.
- **Managing a Global Footprint:** While operating across numerous global markets and regulatory regimes, Standard Chartered concentrates its development teams in a few key hubs to streamline coordination, aiming for a developer self-serve model with appropriate guardrails.
- **Scaling for Blast Radius Analysis:** Looking ahead, Reuben Athaide noted the necessity of running scans in bulk within sandboxed environments rather than repo-by-repo, enabling the bank to evaluate connected applications and understand the full blast radius.
