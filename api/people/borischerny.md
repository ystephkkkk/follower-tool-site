### TL;DR
Boris Cherny, creator of Claude Code at Anthropic, discusses the exponential trajectory of AI coding agents, shifting industry paradigms from deterministic programming to empirical model discovery, and the critical role of safety and alignment research.

### Background & Journey to Anthropic
- **Early Coding Motivation:** Boris Cherny started coding at age 13 on a TI-83 calculator, writing TI-BASIC and Z80 assembly programs to solve math problems and cheat on tests.
- **Startup Career:** Dropped out of college (studying economics) to work on startups—including a chemical analysis venture and an early Y Combinator batch in Palo Alto where he was the first engineering hire—before spending nearly seven years in various technical roles at Meta.
- **Joining Anthropic:** Inspired by sci-fi and a desire to help steer AI development toward a positive future, Cherny and his wife moved from rural Japan to San Francisco to join Anthropic in 2024.

### Model Overhang & The Genesis of Claude Code
- **Model Overhang Concept:** Cherny joined Anthropic's "Labs" team, which focused on bridging the gap between raw model capabilities (starting with the release of Sonnet 3.5) and product limitations.
- **Tool Use Breakthrough:** Claude Code is fundamentally an AI chatbot augmented with tools (initially 4-5 tools like read file, write file, and bash commands), allowing the model to act in the world and execute multi-step tasks without constant human copy-pasting.
- **Prolific Output:** In a span of a few months, the small Labs team produced Claude Code, MCP (Model Context Protocol), the Claude desktop app, early computer use prototypes, and Skills.

### Safety, Alignment, and Security
- **Three Layers of Safety:** Anthropic evaluates safety through (1) artificial benchmarks/evals, (2) mechanistic interpretability (mapping model neurons to animal brain similarities), and (3) real-world observation in the wild.
- **Prompt Injection Defense:** By monitoring characteristic neuron activation patterns during attacks, Anthropic deployed neural probes that successfully shut down prompt injections.
- **Auto Mode:** Recognizing that humans rubber-stamp "yes/no" command prompts as "security theater," Anthropic created Auto mode, where a separate model with no conversation context evaluates command safety, achieving near-perfect accuracy.
- **Zero Prompt Injection Success:** Following multi-year investments in alignment, mechanistic probes, and classifiers, external security researchers failed to demonstrate a successful prompt injection vulnerability during a $20,000 bounty week.
- **Sandboxing:** Anthropic utilizes and open-sources secure sandboxes (containers with restricted network and file access) to ensure agents cannot escape or cause damage.

### Business Growth & Internal Usage
- **Revenue and User Metrics:** After revenue was stuck at $40 million for six months, the release of Opus 4 and Sonnet 4 in May catalyzed accelerated growth; Claude Code now generates billions in revenue with millions of users globally.
- **Internal Adoption:** Nearly 100% of Anthropic employees use Claude Code daily, generating hundreds of agents per employee; all Anthropic products are built using Claude Code with virtually zero human-written code remaining.
- **New Form Factors:** Anthropic continues to experiment beyond the terminal with multiplayer Slack integration ("Claude Tag") and desktop workspace projects.

### Software Engineering & The Future of Work
- **The Printing Press Analogy:** Cherny compares the automation of coding to the printing press, predicting that the distinction between professional software engineers and non-programmers will continue to shrink until coding becomes a basic universal skill like reading and writing.
- **Empirical Science vs. Deterministic Engineering:** Building on LLMs feels less like traditional computer science and more like biology or a social science—requiring empirical observation of an "alien creature" rather than relying on deterministic intuition.
- **Future Desired Traits:** As AI handles routine code, the standout engineer will possess curiosity, strong business judgment, cross-functional communication, and accountability rather than narrow technical specialization.

### TL;DR
Agentic AI is fundamentally transforming software development and organizational workflows, enabling exponential productivity gains, multi-agent orchestration, and autonomous execution.

### Evolution of Development and Agentic Workflows
* **Transition to Autonomous Agents:** 
  * Early AI developer tools functioned as "fancy autocomplete," but scaling laws and increasing model intelligence (beginning broadly with Claude 3.5 and maturing with Opus 4 in May 2025) drove the shift to fully agentic workflows.
* **Orchestration Shift:** 
  * Instead of deterministic, step-by-step programming, users now provide models with a goal, starting point, and tools, letting the model coordinate its own multi-agent workflows.
* **Nested Sub-Agents:** 
  * Claude Code supports up to five layers of nested sub-agents, where agents can spawn and manage other agents to tackle massive workloads.
* **Real-World Scale Examples:** 
  * Large-scale code migrations that previously took months (such as a 10,000-line Scala to Java migration or migrating Bun from Zig to Rust) can now be accomplished in days using divide-and-conquer agent teams.

### AI-Native Culture and Organizational Impact
* **Centralized AI Integration:** 
  * At Anthropic, Claude is placed at the center of every business process, from onboarding and wiki lookups to expense reports, code writing, code review, security review, product brainstorming, and GTM strategy.
* **Productivity Gains:** 
  * Anthropic reports an **8x increase** in code output per engineer, driven by systematically un-bottlenecking one part of the software development lifecycle (SDLC) at a time.
* **Democratization of Problem Solving:** 
  * Agentic tools enable junior engineers, marketers, and non-traditional hires to experiment, solve complex bugs, and bring ideas to market without relying on massive bureaucratic processes.
* **Parallel Workflows:** 
  * Engineers have evolved from running one agent to running dozens or hundreds in parallel, acting as orchestrators while models execute asynchronous tasks.

### Trust, Verification, and Safety Architecture
* **Advanced Model Alignment:** 
  * Anthropic’s models (such as Opus 4.7 and 4.8) are trained for truthfulness and anti-sycophancy, ensuring the model actively pushes back against bad user suggestions rather than blindly agreeing.
* **Security and Anti-Injection:** 
  * Combined model training and runtime classifiers make Anthropic's models among the least prompt-injectable in the industry (outperforming competitors by a margin of 5 to 10x).
* **Auto Mode:** 
  * To prevent human fatigue and rubber-stamping during long-running workflows, Anthropic utilizes classifiers and rigorous red-teaming/pen-testing to run agents safely on "auto mode."
* **Evaluation Frameworks:** 
  * Teams use a combination of automated evals (benchmarks for high-volume workflows) and vibes (intuition for product experiences) to measure and select the best approaches.

### Leadership and Experimentation Strategy
* **Focus on the Return (R):** 
  * Rather than obsessing purely over cost-cutting (the investment side), organizations must give engineers and employees the freedom to experiment and drive the return.
* **Creating Safe Spaces:** 
  * Leaders must actively create psychological safety, encouraging experimentation and treating non-traditional backgrounds and side projects as indicators of high performance.

### Predictions & Forward Calls
* **Agent Runtime Timelines:** Boris Cherny predicts that within 6 months, it will become normal for engineers and workers to run agents for days or weeks at a time with a high degree of autonomy and less hand-holding.
* **Autonomous Startups:** Boris Cherny predicts that by the end of the year, Claude will be used to build not just features or products, but entire businesses and startups.

## Boris Cherny: Building Claude Code

### TL;DR
Claude Code creator Boris Cherny announced the launch of Opus 5, highlighting its extended execution capabilities, near-zero prompt-injectability, and massive 80% system prompt reduction. Cherny emphasized that building with modern AI requires an empirical mindset—regularly "pressing delete" on legacy prompts and harnesses to unhobble models for complex, multi-week agentic workflows.

### Opus 5 Capabilities & Alignment
- **Extended Autonomous Execution:** Unlike previous models, Opus 5 can run continuously for days, weeks, or months without stopping, even without complex scaffolding like SLoG or Sloop.
- **Elimination of Prompt Injection:** By combining three layers—three years of alignment research, a prompt injection classifier based on Chris Olah's mechanistic interpretability work (detecting specific neurons lighting up), and an auto mode classifier—Opus 5 has become essentially prompt-injectable-free (a milestone achieved progressively since Opus 4.7/4.8 and Sonnet 5).
- **Vision and Computer Use:** Opus 5 represents a massive leap in vision and computer use, demonstrated by spontaneous capabilities such as drawing complex portraits, animals, and landscapes using OpenCV without explicit training.

### The "Press Delete" Product Strategy
- **System Prompt Ablation:** For every new model release, Anthropic deletes large portions of Claude Code's system prompt and tools, then rebuilds them line by line to determine what the new model actually requires.
- **Simple Mode Ablation:** Claude Code includes an undocumented feature (`CLAUDE_CODE_SIMPLE=1`) that deletes all system prompts from both the product and its tools; tests show the model is often slightly more intelligent without these legacy instructions.
- **Actionable Advice for Founders:** Cherny recommends that developers and founders using Claude Code delete their `CLAUDE.md`, skills, and hooks every six months to test what the model can do natively without legacy instructions.

### Unhobbling Models & Product Overhang
- **Product Overhang Defined:** The gap between what a model is currently capable of doing and what existing products allow it to do; scaffolding and rigid product design often "hobble" the model by getting in its way.
- **Giving Harder Tasks:** Users commonly make the mistake of giving overly specific, step-by-step instructions (e.g., "must do 1, then 2, then 3"); modern models perform better when given high-level tasks, guardrails, and exit criteria.
- **Real-World Examples of Scale:** 
  - The Bun team used Claude to rewrite an entire JavaScript runtime codebase from Zig to Rust in a single 11-day dynamic workflow prompt (saving over a year of engineering effort on a 100,000+ line codebase).
  - Cherny launched a personal experiment to rewrite the Electron desktop app in Swift inside a Mac virtual machine, having Claude screenshot and compare pixels pixel-by-pixel; the agent has been running autonomously for over two weeks.

### Dynamic Workflows & Autonomous Maintenance
- **Test-Time Compute Scaling:** Dynamic workflows function as an "algebra for agents" (running agents in sequence or parallel within a Bun runtime sandbox) to orchestrate dozens, hundreds, or thousands of agents for complex tasks.
- **Loops and Routines:** Local cron jobs (loops) and cloud-running tasks (routines) allow Claude to maintain Anthropic's own codebases across iOS, Android, desktop, and CLI apps.
- **Automated Codebase Maintenance:** Routine prompts run daily across Anthropic to handle dead code cleanup, feature flag removal, test coverage expansion, removal of obsolete tests, and unifying duplicated code abstractions via the "abstraction police" routine, operating hundreds to thousands of agentic tasks daily.

### Predictions & Forward Calls
- **Boris Cherny** claims that routine agent maintenance will soon fully automate the maintenance of software applications, enabling teams to delegate thousands of daily agentic tasks.

### Notable Quotes

> — Boris Cherny

    * **Switching Costs Will Decrease:** AI agents make it incredibly easy to port data and switch from vendor A to vendor B, eroding traditional software lock-in.
    * **Network Effects and Economies of Scale Will Strengthen:** Structural moats like proprietary user networks and physical manufacturing scale (e.g., TSMC or massive cloud infrastructure) will become even more valuable.

**TL;DR:** Claude Code marks a paradigm shift where AI agents treat coding as a "practically solved" problem, yielding 150% productivity gains at Anthropic and signaling a transition from specialized "Software Engineers" to generalist "Builders" who use agent swarms to execute 100% of their code.

### Design Philosophy: Accidental Simplicity & Latent Demand
*   **The Terminal as a Feature:** Claude Code began as a simple CLI prototype because Boris Cherny wanted to avoid building a complex UI.
    *   **Elegant Constraints:** The terminal’s limitations (no mouse, limited colors) forced a focus on high-speed text interaction.
    *   **Accidental Adoption:** Internal engineers at Anthropic "revolted" when UI simplifications were proposed; they preferred seeing raw bash outputs for transparency.
*   **The Latent Demand Principle:** Boris attributes the product’s success to identifying what users were already trying to do and making it easier.
    *   **CLAUDE.md:** Emerged after observing engineers manually creating markdown files to instruct the model. Boris recommends keeping these files short and deleting them frequently to let the model’s improving core capabilities take over.
    *   **Plan Mode:** Developed in 30 minutes after seeing users struggle to keep the model from "coding too soon."

### Engineering Productivity & The "End of IDEs"
*   **150% Productivity Surge:** Since the launch of Claude Code, productivity per engineer at Anthropic has grown by 150% (measured by PR volume and commit lifetime).
*   **The IDE-less Workflow:** Boris reports he has uninstalled his IDE and lands roughly 20 PRs per day.
    *   **100% AI-Generated:** For high-level engineers at Anthropic, nearly 100% of code is now written by Claude, with humans acting as "architects" or "spec writers."
*   **Global Impact:** Approximately 4% of all public commits globally are now estimated to be made via Claude Code.
*   **CoWork and Non-Technical Users:** The "CoWork" desktop app is essentially a Claude Code wrapper with a GUI/VM, allowing finance, design, and sales teams to automate complex tasks without terminal knowledge.

### Strategic Advice for AI Founders
*   **The 6-Month Rule:** Never build for the capabilities of today’s model. Build for the "frontier" where the model is currently failing, as it will likely succeed there in six months.
*   **Avoid "Scaffolding" Debt:** Boris warns against building heavy code structures to fix model limitations. He views this as "tech debt" that is wiped out the moment a more capable model is released.
*   **The Bitter Lesson:** Anthropic keeps a framed copy of Rich Sutton’s "The Bitter Lesson" on the wall—the belief that general methods that leverage computation always eventually defeat human-designed specialized "tricks."
*   **Recursive Self-Improvement:** Boris suggests that "Plan Mode" may be obsolete within months as models become capable of self-correcting and strategizing without explicit prompting.

### The Future of the "Software Engineer"
*   **The Rise of Hyper-Generalists:** The distinction between PMs, designers, and engineers is blurring. At Anthropic, "everyone codes," including finance and HR, using AI agents.
*   **Agent Topologies:** The future of development lies in "swarms" or "sub-agents."
    *   **Recursive Agents:** Claude Code frequently spawns "sub-agents" to research bugs or test tools in parallel context windows, effectively utilizing "test-time compute."
*   **Safety and ASL-4:** As models reach "AI Safety Level 4" (recursive self-improvement), Anthropic is focusing heavily on preventing catastrophic misuse, such as the autonomous creation of bio-viruses or zero-day exploits.
