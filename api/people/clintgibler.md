## How Mozilla uses GPT-6 Cyber to find and fix Firefox vulnerabilities

- Channel: OpenAI
- Video: https://www.youtube.com/watch?v=PkAmyub12K8
- Published: 2026-11-13
- Briefing: https://ystephkkkk.github.io/follower-tool-site/20261113.html#video-PkAmyub12K8
- Speakers: Brian Grinstead (Security Engineer, Mozilla); Clint Gibler (Cybersecurity Lead, OpenAI)

### TL;DR
By combining decades of browser security preparation with GPT-6 Cyber agents, Mozilla scaled its bug discovery and fix rate by 8× from 2025 to 2026, successfully preventing any successful exploits at the annual Pwn2Own competition.

### 1. Pwn2Own Fire Drill and Agentic Partnerships
* **Pre-Competition Scramble:** Browsers remain a top target for the annual Pwn2Own hacking competition, which Mozilla uses as a real-world fire drill.
  * **OpenAI Collaboration:** Shortly before the 2026 event, the OpenAI cyber team filed a few bugs; after Mozilla quickly fixed and uplifted them, it was discovered that a number of researcher submissions were attempting to use those exact bugs.
  * **Event Outcome:** Mozilla successfully defended Firefox, with no participants able to compromise the browser.

### 2. Decades of Foundational Security Preparation
* **Prerequisites for AI Integration:** Mozilla’s ability to successfully adopt an agentic tool chain was built on years of foundational security investments.
  * **External Bug Bounties:** Decades of running an external bug bounty program established comfort with receiving a high volume of external reports.
  * **Internal Tooling:** Long-standing adoption of address sanitizers, fuzzers, debuggable builds, and internal red teams provided the exact primitives agents now use to spin up Firefox instances, test potential exploits, and iterate rapidly.

### 3. Agentic Security Pipeline & Inner Loop Architecture
* **Intelligent File Prioritization:** Alphabetical file-tree scanning proved ineffective, leading Mozilla to use an LLM-based grading system incorporating technical documentation, researcher artifacts, and historical risk scores to generate target lists.
* **Inner Loop Execution:** 
  * **VM Isolation & Goals:** An agent is placed inside its own VM with access to the Firefox source code and fuzzing tool chain, tasked with finding bugs via static analysis, custom mini-fuzzers, and dynamic testing.
  * **Deterministic Verification:** The agent must produce deterministic proof (such as an HTML file causing a crash in Firefox) to exit the inner loop.
* **Secondary Judging & Quality Control:** 
  * A second grading agent checks the work to catch anomalies (such as an agent artificially patching the codebase to force a crash) and grade severity against Mozilla's threat model, resulting in a tiny false positive rate.
  * **Auto-Fix Generation:** Within the inner loop, an agent generates a code patch and a test case to accompany the bug report.

### 4. Scaling Triage, Deduplication, and Variant Analysis
* **Automated Deduplication Challenges:** Distinguishing unique vulnerabilities from hundreds of scan findings proved unintuitively difficult due to nuanced crash stack variations.
  * **Database Ingestion:** Mozilla ingests all findings into a local database and tasks an agent with connecting dots under strict guidance.
  * **False Duplicate Safeguards:** If a finding is marked as a duplicate, the system creates a reminder to confirm it no longer works once the primary bug lands in the tree.
* **Severity Re-Evaluation via GPT-6 Cyber:** Powerful cyber models uncovered that certain bugs originally graded as moderate/low severity actually bypassed architectural hardening and qualified as security-high, providing vital feedback to improve defense-in-depth.
* **Broad Variant and Commit Scanning:** 
  * **Variant Analysis:** Bundling known security bugs fixed in 2025 and tasking agents to hunt for similar patterns across the codebase yielded a majority of findings by September, generating fewer duplicate reports.
  * **Commit Scanning:** Narrowly inspecting new commits for potential vulnerabilities works alongside broad variant scans as part of the core strategy.

### 5. Engineer Workflows and 8× Metric Scaling
* **Assisting Human Engineers:** While generated fix patches are rarely landable as-is due to narrow targeting or missing codebase context, expert browser engineers use them alongside descriptions and evidence to review and land fixes.
* **Massive Productivity Gains:** Across its security workflow, Mozilla achieved an **8× increase in bug discovery and fixes** from **2025 to 2026**.
* **Agentic Vulnerability Workbench:** 
  * **SQLite Ingestion:** Signals from all runs, bugs, and engineer comments are ingested into a local SQLite file on red team engineers' machines.
  * **Workflow Queries:** Coding agents can run SQL queries to plan next scanning patches based on Slack hints or review raw traces and `blockers.yaml` files to fix environment dependencies.
