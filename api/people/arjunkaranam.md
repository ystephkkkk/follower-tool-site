### TL;DR
Arjun Karanam of Trajectory introduces continual learning to close the "experience gap" in AI models, turning discarded interaction tokens into training signals that compound agent performance with every use.

### The Experience Gap & The Continual Learning Thesis
* **The IQ vs. Experience Disconnect:** Models improve rapidly on intelligence (IQ), but every interaction still feels like a first-day-on-the-job experience.
* **The Value of Discarded Interactions:** Hundreds of millions of tokens generated by agents are thrown away daily; Trajectory treats these real work traces as a critical training signal.
* **Compound Systems:** The goal is to move from static, error-prone agents to learning agents that get faster, better, and cheaper with use, creating compounding system capabilities.

### Four Pillars of Continual Learning Infrastructure
* **Full Traceability:** 
  * Capture the entire tree of execution, including tool calls and sub-agents, rather than just main actions.
  * Elicit and capture corrective behavior—such as edits, undos, and retries—rather than relying solely on noisy thumbs-up/thumbs-down signals.
* **Production-Driven Evals:** 
  * Draw evals directly from real production traffic and frontier user requests.
  * Build infrastructure that makes every user task rollout re-playable and grades against the real harnesses used in production.
* **Unconstrained Harnesses:** 
  * Shift from harnesses designed to prevent bad behavior (legacy model constraints) to "let the agents cook" setups where agents orchestrate product primitives.
  * Align the agent interface with the UI so agents can perform every user-facing action via tool calls, backed by informative tool responses (avoiding vague "done/finished" states).
* **Open Weights & Model Routing:** 
  * Run on open weights to unlock the ability to own and continually improve model weights.
  * Experiment with model routers to direct tasks to the right capability tier.

### Handling Data Privacy and Feedback Hierarchy
* **Synthetic Distribution Sampling:** To avoid training directly on sensitive customer data, Trajectory samples distributions from customer data and synthetically generates training sets, verifying alignment via distribution comparison.
* **Feedback Categorization:** 
  * *Negative signal without correction* (e.g., sessions with negative feedback or drop-offs) is used to penalize bad behavior.
  * *Corrected paths* (e.g., retries and edits) provide high-confidence reward signals.
* **Updating Strategy (Weights vs. Context):** Global patterns (like a repeatedly failing tool call) are trained into model weights, while customer-specific preferences or local context remain in the harness/context layer.
