## When to Build Your Own Agent Harness | Harrison Chase, LangChain

- Channel: Sequoia Capital

### TL;DR
Harrison Chase explains that building an agent requires balancing three core components—harness, model, and context—and advocates starting with general off-the-shelf harnesses before customizing via middleware as tasks move out-of-distribution.

### Anatomy of an Agent: Harness, Model, and Context
* **The Three Core Pillars:** According to LangChain, every agent consists of a harness, a model, and context; owning your intelligence requires owning all three parts.
    * **Model Flexibility:** Being able to switch between open weight and proprietary models avoids vendor lock-in and ensures you always use the best available model.
    * **Context Management:** Managing memory, semantic knowledge, and previous conversations helps personalize and guide the agent's behavior.
    * **Harness Orchestration:** The harness acts as the orchestrator, bringing dynamic and fixed context into the model's context window at the right point in time.
* **The Core Agent Loop:** At its simplest, an agent is an LLM running in a loop that calls tools, evaluates observations, and passes them back to the model.

### Customizing Harnesses with Middleware and Model Profiles
* **Using Middleware for Customization:** Developers can modify the base agent loop using small middleware constructs, hooks, and plugins without rewriting the core architecture.
    * **Enabled Capabilities:** Middleware allows harnesses to connect to sandboxes, file systems, sub-agents, memory, and summarization steps.
    * **Context Offloading:** Large tool calls can be wrapped and dumped to manage context length efficiently.
* **In-Distribution vs. Out-of-Distribution Tasks:** The more out-of-distribution a task is, the more customization your harness requires.
    * **Keeping In-Distribution Sub-Tasks Close to the Model:** Even on custom out-of-distribution tasks (like legal AI), foundational sub-tasks like file editing should mirror what the model was explicitly RL'd on.
    * **Model Profiles:** Deep Agents utilizes model profiles to dynamically switch between different file-edit implementations depending on whether an OpenAI or Anthropic model is active.

### Evals, Benchmarks, and Observability
* **Setting Private Evals:** Mirroring Satya's framing, organizations must create private evaluations to define what "good" looks like and build a continuous hill-climbing improvement loop.
* **Harbor as an Open-Source Standard:** Harbor has emerged as an industry-standard open-source eval runner (created by the makers of Terminal Bench 2) used to run data sets in sandboxed Dockerfile environments.
* **Comprehensive Benchmarking:** Benchmarks should track not just accuracy, but also latency and token cost across different agent harnesses, models, and reasoning efforts.
* **Observability and Trajectories:** Observability is critical for debugging why an LLM call failed—usually resulting from poor context accumulation rather than an inadequate model.
    * **Message Trajectories:** Agents run primarily on message trajectories (human inputs followed by underlying tool-call messages and responses).
    * **Debugging Views:** Platforms like LangSmith provide both user-friendly summarized views and deep trace views to inspect exact model inputs and outputs.

### The Data Flywheel and Automated Harness Engineering
* **Continuous Improvement Recipe:** Build an agent, collect traces, curate trace data, and run experiments to update any part of the agent (harness, model, or context).
* **Feedback Mechanisms:** Collecting high-quality feedback relies on clever UX design to capture implicit user signals, combined with fast, low-cost synthetic feedback from fine-tuned Small Language Models (SLMs) acting as judges.
* **LangSmith Engine:** LangChain built Engine—an internal background agent that sits on top of LangSmith traces, runs using a coding agent with a LangSmith CLI, and automatically generates issue boards, prompt updates, and harness code changes.

## Harrison Chase of LangChain on Deep Agents, LangSmith, and Earning Trust | NVIDIA AI Podcast Ep. 297

- Published: 2026-05-06

- Speakers: Harrison Chase (co-founder & CEO, LangChain)

---

**TL;DR**
LangChain is shifting its focus toward "deep agents"—autonomous, general-purpose harnesses that move beyond simple LLM wrappers to sophisticated systems capable of background execution, proactive task management, and persistent identity. Harrison Chase argues that the next phase of enterprise productivity relies on evaluation-driven development and the strategic mixing of frontier and open-source models (like NVIDIA Nemotron) to manage costs and data sensitivity.

### The Architecture of "Deep Agents"
* **General-Purpose Harnesses:** Deep agents represent a move toward a standard architecture where an LLM runs in a loop, interacting with tools, sub-agents, and file systems.
    * **Simplicity as Power:** Chase notes that successful systems like Claude Code, Manus, and Deep Research share a foundational pattern of giving LLMs autonomy within a simple, customizable scaffold rather than reinventing the architecture for every task.
* **LangGraph vs. Deep Agents:** While deep agents offer high autonomy, many enterprises still prefer LangGraph for use cases requiring directed workflows and more rigid control.
* **Model Agnostic Open Source:** LangChain’s deep agent library is designed to be model-agnostic, allowing developers to customize agents via prompts and tools rather than hard-coded logic.

### Enterprise Trust through Evaluation-Driven Development
* **The "Build-Test-Run-Manage" Lifecycle:** Chase utilizes LangSmith as the primary platform for observability and tracing to solve the non-deterministic nature of LLMs.
* **Evaluation Scenarios:** Trust is built by creating specific test scenarios (starting with as few as 5–10) to benchmark agent performance.
    * **Product Thinking:** Evals force developers to define exactly what an agent *should* and *should-not* do, creating a mental model for guardrails.
* **The 9-Month Rewrite Rule:** Because the AI space evolves so rapidly, Chase advises enterprises that any agent architecture older than nine months is likely obsolete and should be re-evaluated for performance and scope.

### The Role of Open Models and NVIDIA Nemotron
* **Hybrid Model Strategies:** Enterprises are increasingly using "orchestrator" agents powered by frontier models (like GPT-4 or Claude 3.5) while delegating specific tasks to specialized sub-agents powered by open-source or fine-tuned models.
* **Cost and Proactivity:** Open-source models are essential for "always-on" proactive agents. Chase notes that running a high-frequency agent on frontier APIs is cost-prohibitive, whereas open models enable continuous event-listening.
* **Coding Models as Engines:** Models optimized for coding (e.g., Qwen-Coder) are often superior general-purpose agents because the "harness" they operate in (bash tools, file systems) mimics a coding environment.
* **Open Runtimes:** Beyond models, Chase highlights the importance of secure, open runtimes like NVIDIA OpenShell for running agentic workloads safely.

### Future Trends: Asynchronicity, Memory, and Identity
* **Asynchronous Sub-agents:** Future systems will feature orchestrators that spin up multiple long-running background agents, allowing the user to "check in" on progress rather than waiting for a linear response.
* **Proactive Productivity:** The next major unlock is "event-driven" agents that listen to enterprise triggers (like emails or database changes) to prepare drafts or actions for human approval.
* **Agent Memory:** Agents are beginning to learn from interactions, updating their own tools, skills, and descriptions based on human-in-the-loop feedback.
* **The Identity Shift:** Chase predicts a move from agents acting "on behalf of" a user to agents having their own distinct identities (e.g., a "Marketing Agent" with its own Slack and Gmail credentials) and persistent memories.
