## What Comes After Loops?: Deep Dive Into Agentic Architecture | DevDay 2026

- **TL;DR:** OpenAI engineers Raj Bhatek and Eric traced the evolution of AI agents from simple prompt-response loops to collaborative, multi-agent systems—culminating in a massive 10,000-agent architecture that successfully tackled the Navier-Stokes Millennium Prize problem.

### Evolution of Agentic Architecture: From Loops to Codex
- **Initial Paradigm Shift:** 
  - Early AI interactions required manual human intervention (e.g., copying and pasting code like FizzBuzz).
  - The introduction of reasoning combined with tool use (such as in the o3 launch) created the foundational "agentic loop."
- **The Codex General Agent:**
  - Built as a union of a model and a harness working together; OpenAI open-sourced Codex with a minimal, opinionated design giving models access to a computer via shell, file system, and computer use.
  - The **Responses API** manages the tool-call loop, execution sandbox, and conversation context.
- **Solving Long-Horizon Work via Compaction:**
  - Early models hit context window limits and stopped prematurely.
  - OpenAI trained **native compaction** into both the harness and model (accessible via the `/compact` endpoint in the Responses API), allowing models to resume from a condensed state and handle multi-window tasks.
- **From Outer Loops to Native Persistence:**
  - Developers initially used manual scripts or brute-force loops (like Geoffrey Huntley's "Ralph loop" or using `continue` statements) to keep models working.
  - Introduced `--goal` in GPT-5.5 to track objectives outside the core context window.
  - With GPT-5.6, persistence was trained directly into the model, eliminating the need for `--goal` hacks. Wharton professor Ethan Mullica notably tested this by having Codex play *Slay the Spire 2* for five hours straight.

### Multi-Agent Workflows & Best Practices
- **Scaling from Single Agents:**
  - Eric (DX team) advises starting with a single agent and clear verification methods for tasks before scaling up to teams.
- **Autonomous Coordination (GPT-6):**
  - GPT-6 series models can coordinate and collaborate natively, breaking down massive tasks (like full codebase refactors or game ports) by spinning up subagents (e.g., Ultra) autonomously.
- **Agent Geometries and Effort Scaling:**
  - **Effort Scaling:** Dynamically assigns reasoning effort and models using subagents (e.g., Sol managing integration, Astra handling difficult test failures, and Luna taking on simple busy work).
  - **The Pair Pattern:** Deploying a pair of subagents with explicit communication boundaries (e.g., one agent handling capture tech in an old game engine, the other unpacking/visualizing the scene in Blender).
  - **Thread Managers:** Using ChatGPT app threads to spin up and manage separate conversations for discrete tasks (like a separate chat for every PR in a review queue) while keeping the manager informed.
  - **Departmental Roles:** Structuring long-running projects (like video games) by assigning agents distinct lanes (art director, playtester, programmer, producer).
- **Pitfalls to Avoid:**
  - **Middle Management Tax:** Overcomplicating agent hierarchies with too many rules causes agents to stall seeking approval.
  - **Context Drift & The Work Log:** To counteract short-term memory loss and constant human nagging/steering, prompt Codex to maintain a compact work log containing the overall goal, running work, and how recent steering relates to both.

### Scaling to the Next Generation: Agent Teams
- **Massive-Scale Collaboration:**
  - Moving beyond a handful of agents to thousands (e.g., 10,000 agents) to tackle massive, complex problems.
- **The Navier-Stokes Breakthrough:**
  - OpenAI utilized an internal advanced model alongside Codex to solve the long-standing Millennium Prize Navier-Stokes problem using **10,000 agents**, generating **2.7 million messages** and **130 billion output tokens**.
- **Agent Team Architecture:**
  - **Unified Goal with Diversity:** Initialized multiple teams with different versions of a problem to encourage varied approaches and prevent duplicative effort.
  - **Cross-Team Communication:** Agents share findings and ask questions across different teams.
  - **Dynamic Orchestration:** As hypotheses were explored and new questions arose, teams were dynamically created, steered, or redirected toward promising lines (e.g., all teams being diverted to the unforced Euler result once found).
  - **Broader Impact:** Using this internal model architecture, OpenAI resolved more than **100 longstanding problems** across mathematics and continues making discoveries in math and science.
