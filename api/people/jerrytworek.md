### TL;DR
Jerry Tworek and Rohan Anil founded Core Automation on the contrarian premise that the transformer architecture has hit a ceiling and the true bottleneck to smarter systems is continual learning at test time. The lab aims to build the world's most automated research organization—starting with automated kernel generation—to discover a scalable transformer replacement.

### The Transformer Bottleneck & The Case for Continual Learning
* **Transformer Limitations:** 
  * Transformers excel at distilling internet knowledge and baking workflows via pre-training and RL, but they cannot adapt post-training without catastrophic forgetting (via fine-tuning) or severe data limits (via 20-minute in-context learning windows like Codex).
  * Real-world task distributions are messier and shift constantly; models trained in labs become obsolete if underlying events, codebases, or tools change.
* **Poor Computational Depth:** 
  * According to Rohan Anil, transformers are shallow (at most ~100 layers deep). While inference-time scaling (chain-of-thought token generation) adds computational depth, generating one token at a time autoregressively is highly inefficient.
* **The RL Disappointment:** 
  * Jerry Tworek shares that despite scaling up reinforcement learning at OpenAI expecting it to solve real-world tasks, evaluation benchmarks matched training tasks while real-world distributions remained unreached.

### The Architectural & Optimization Vision
* **End-to-End Optimization:** 
  * Pre-training and RL must be optimized together end-to-end rather than treated as isolated phases, forming a cohesive learning procedure.
* **Optimization-Architecture Symbiosis:** 
  * Rohan Anil's work on the Shampoo optimizer demonstrates that stronger optimization algorithms enable the training of harder-to-optimize models, allowing researchers to explore deeper representations and alternative architectures (such as removing residual connections or utilizing N-gram memory embeddings).
* **Hardware Efficiency & Scale:** 
  * Any new architecture must run efficiently on physical hardware; architectural innovation without production-grade kernel generation is theoretically incomplete.

### Why Start a New Lab?
* **Competitive Distractions at Big Labs:** 
  * Frontier labs are locked in a high-stakes coding-agent market race and rely on profitable transformers to win quarterly cycles, leaving little organizational bandwidth to pursue alternative architectures.
* **The Core Automation Approach:** 
  * By building a lab natively designed for agentic automation, the team aims to run deep learning stack experiments at high iteration speeds (targeting multiple experiments per day) rather than operating in slow, siloed research units.

### The Roadmap: Automating Kernel Generation
* **The Hardware-Software Bottleneck:** 
  * Core Automation's immediate 6-month roadmap focuses on automating kernel generation to run custom matrix operations and linear algebra routines (such as QR factorization for the Shampoo optimizer) at peak TFLOPS on GPUs.
* **The Human Taste Gap:** 
  * While human-plus-search loops currently achieve significant speedups (e.g., a GPU Mode QR kernel competition where a top-tier human plus $100,000 in coding agent spending over 4 weeks yielded a 60x speedup), frontier models like Gemini, Claude, and OpenAI models cannot solve these complex multi-operator kernel problems autonomously. Core Automation aims to bridge this gap.
