## How Mozilla uses GPT-6 Cyber to find and fix Firefox vulnerabilities

- Channel: OpenAI
- Video: https://www.youtube.com/watch?v=PkAmyub12K8

- Speakers: Brian Grinstead (Security Engineer, Mozilla); Clint Gibler (Cybersecurity Lead, OpenAI)

---

### TL;DR
By combining decades of browser security preparation with GPT-6 Cyber agents, Mozilla scaled its bug discovery and fix rate by 8× from 2025 to 2026, successfully preventing any successful exploits at the annual Pwn2Own competition.

### 1. Pwn2Own Fire Drill and Agentic Partnerships
* **Pre-Competition Scramble:** Browsers remain a top target for the annual Pwn2Own hacking competition, which Mozilla uses as a real-world fire drill.
  * **OpenAI Collaboration:** Shortly before the 2026 event, the OpenAI cyber team filed a few bugs; after Mozilla quickly fixed and uplifted them, it was discovered that a number of researcher submissions were attempting to use those exact bugs.
  * **Event Outcome:** Mozilla successfully defended Firefox, with no participants able to compromise the browser.

### 2. Decades of Foundational Security Preparation
* **Prerequisites for AI Integration:** Mozilla’s ability to successfully adopt an agentic tool chain was built on years of foundational security investments.
  * **External Bug Bounties:** Decades of running an external bug bounty program established comfort with receiving a high volume of external reports.
  * **Internal Tooling:** Long-standing adoption of address sanitizers, fuzzers, debuggable builds, and internal red teams provided the exact primitives agents now use to spin up Firefox instances, test potential exploits, and iterate rapidly.

### 3. Agentic Security Pipeline & Inner Loop Architecture
* **Intelligent File Prioritization:** Alphabetical file-tree scanning proved ineffective, leading Mozilla to use an LLM-based grading system incorporating technical documentation, researcher artifacts, and historical risk scores to generate target lists.
* **Inner Loop Execution:** 
  * **VM Isolation & Goals:** An agent is placed inside its own VM with access to the Firefox source code and fuzzing tool chain, tasked with finding bugs via static analysis, custom mini-fuzzers, and dynamic testing.
  * **Deterministic Verification:** The agent must produce deterministic proof (such as an HTML file causing a crash in Firefox) to exit the inner loop.
* **Secondary Judging & Quality Control:** 
  * A second grading agent checks the work to catch anomalies (such as an agent artificially patching the codebase to force a crash) and grade severity against Mozilla's threat model, resulting in a tiny false positive rate.
  * **Auto-Fix Generation:** Within the inner loop, an agent generates a code patch and a test case to accompany the bug report.

### 4. Scaling Triage, Deduplication, and Variant Analysis
* **Automated Deduplication Challenges:** Distinguishing unique vulnerabilities from hundreds of scan findings proved unintuitively difficult due to nuanced crash stack variations.
  * **Database Ingestion:** Mozilla ingests all findings into a local database and tasks an agent with connecting dots under strict guidance.
  * **False Duplicate Safeguards:** If a finding is marked as a duplicate, the system creates a reminder to confirm it no longer works once the primary bug lands in the tree.
* **Severity Re-Evaluation via GPT-6 Cyber:** Powerful cyber models uncovered that certain bugs originally graded as moderate/low severity actually bypassed architectural hardening and qualified as security-high, providing vital feedback to improve defense-in-depth.
* **Broad Variant and Commit Scanning:** 
  * **Variant Analysis:** Bundling known security bugs fixed in 2025 and tasking agents to hunt for similar patterns across the codebase yielded a majority of findings by September, generating fewer duplicate reports.
  * **Commit Scanning:** Narrowly inspecting new commits for potential vulnerabilities works alongside broad variant scans as part of the core strategy.

### 5. Engineer Workflows and 8× Metric Scaling
* **Assisting Human Engineers:** While generated fix patches are rarely landable as-is due to narrow targeting or missing codebase context, expert browser engineers use them alongside descriptions and evidence to review and land fixes.
* **Massive Productivity Gains:** Across its security workflow, Mozilla achieved an **8× increase in bug discovery and fixes** from **2025 to 2026**.
* **Agentic Vulnerability Workbench:** 
  * **SQLite Ingestion:** Signals from all runs, bugs, and engineer comments are ingested into a local SQLite file on red team engineers' machines.
  * **Workflow Queries:** Coding agents can run SQL queries to plan next scanning patches based on Slack hints or review raw traces and `blockers.yaml` files to fix environment dependencies.

## What Comes After Loops?: Deep Dive Into Agentic Architecture | DevDay 2026

- Channel: OpenAI
- Video: https://www.youtube.com/watch?v=nAubbmlhPfI
- Published: 2026-11-11
- Briefing: https://ystephkkkk.github.io/follower-tool-site/20261111.html#video-nAubbmlhPfI
- Speakers: Raj Bhatek (Engineer, OpenAI); Eric (Engineer, OpenAI)

---

- **TL;DR:** OpenAI engineers Raj Bhatek and Eric traced the evolution of AI agents from simple prompt-response loops to collaborative, multi-agent systems—culminating in a massive 10,000-agent architecture that successfully tackled the Navier-Stokes Millennium Prize problem.

### Evolution of Agentic Architecture: From Loops to Codex
- **Initial Paradigm Shift:** 
  - Early AI interactions required manual human intervention (e.g., copying and pasting code like FizzBuzz).
  - The introduction of reasoning combined with tool use (such as in the o3 launch) created the foundational "agentic loop."
- **The Codex General Agent:**
  - Built as a union of a model and a harness working together; OpenAI open-sourced Codex with a minimal, opinionated design giving models access to a computer via shell, file system, and computer use.
  - The **Responses API** manages the tool-call loop, execution sandbox, and conversation context.
- **Solving Long-Horizon Work via Compaction:**
  - Early models hit context window limits and stopped prematurely.
  - OpenAI trained **native compaction** into both the harness and model (accessible via the `/compact` endpoint in the Responses API), allowing models to resume from a condensed state and handle multi-window tasks.
- **From Outer Loops to Native Persistence:**
  - Developers initially used manual scripts or brute-force loops (like Geoffrey Huntley's "Ralph loop" or using `continue` statements) to keep models working.
  - Introduced `--goal` in GPT-5.5 to track objectives outside the core context window.
  - With GPT-5.6, persistence was trained directly into the model, eliminating the need for `--goal` hacks. Wharton professor Ethan Mullica notably tested this by having Codex play *Slay the Spire 2* for five hours straight.

### Multi-Agent Workflows & Best Practices
- **Scaling from Single Agents:**
  - Eric (DX team) advises starting with a single agent and clear verification methods for tasks before scaling up to teams.
- **Autonomous Coordination (GPT-6):**
  - GPT-6 series models can coordinate and collaborate natively, breaking down massive tasks (like full codebase refactors or game ports) by spinning up subagents (e.g., Ultra) autonomously.
- **Agent Geometries and Effort Scaling:**
  - **Effort Scaling:** Dynamically assigns reasoning effort and models using subagents (e.g., Sol managing integration, Astra handling difficult test failures, and Luna taking on simple busy work).
  - **The Pair Pattern:** Deploying a pair of subagents with explicit communication boundaries (e.g., one agent handling capture tech in an old game engine, the other unpacking/visualizing the scene in Blender).
  - **Thread Managers:** Using ChatGPT app threads to spin up and manage separate conversations for discrete tasks (like a separate chat for every PR in a review queue) while keeping the manager informed.
  - **Departmental Roles:** Structuring long-running projects (like video games) by assigning agents distinct lanes (art director, playtester, programmer, producer).
- **Pitfalls to Avoid:**
  - **Middle Management Tax:** Overcomplicating agent hierarchies with too many rules causes agents to stall seeking approval.
  - **Context Drift & The Work Log:** To counteract short-term memory loss and constant human nagging/steering, prompt Codex to maintain a compact work log containing the overall goal, running work, and how recent steering relates to both.

### Scaling to the Next Generation: Agent Teams
- **Massive-Scale Collaboration:**
  - Moving beyond a handful of agents to thousands (e.g., 10,000 agents) to tackle massive, complex problems.
- **The Navier-Stokes Breakthrough:**
  - OpenAI utilized an internal advanced model alongside Codex to solve the long-standing Millennium Prize Navier-Stokes problem using **10,000 agents**, generating **2.7 million messages** and **130 billion output tokens**.
- **Agent Team Architecture:**
  - **Unified Goal with Diversity:** Initialized multiple teams with different versions of a problem to encourage varied approaches and prevent duplicative effort.
  - **Cross-Team Communication:** Agents share findings and ask questions across different teams.
  - **Dynamic Orchestration:** As hypotheses were explored and new questions arose, teams were dynamically created, steered, or redirected toward promising lines (e.g., all teams being diverted to the unforced Euler result once found).
  - **Broader Impact:** Using this internal model architecture, OpenAI resolved more than **100 longstanding problems** across mathematics and continues making discoveries in math and science.

## Why Sam Altman is against a single superintelligence

- Channel: Cheeky Pint
- Video: https://www.youtube.com/watch?v=iMsUcCYNKqY
- Published: 2026-10-29

---

### TL;DR
Sam Altman breaks down how OpenAI's agent teams unlocked breakthroughs in PHP cybersecurity and complex math like Navier-Stokes, while warning that sandboxing superhuman models is an unsolved safety dilemma that necessitates decentralized agent swarms over a single superintelligence.

### Cybersecurity, Software Re-Architecture, and Vulnerabilities
- **PHP Vulnerability Discovery:** OpenAI models uncovered significant vulnerabilities in PHP codebases that had gone unnoticed for 20 years, proving that AI can rapidly scan and expose widespread security weaknesses on the internet.
- **Global Software Upgrade:** Altman believes the industry will move beyond merely fixing old software to fundamentally re-architecting routers, operating systems, and entire application stacks using AI tools.
- **Cyber Blue Capabilities:** During initial deployments of OpenAI's cyber tools, individual companies successfully used models not only to build patches and run defense, but also to quickly scan codebases and take applications offline for rapid repairs.
- **Threat Model Uncertainty:** Cyber experts are losing confidence in traditional security threat assumptions because advanced AI might discover deep, novel hardware bugs grounded in physics principles previously not understood.

### Safety, Sandboxing, and Agent Teams
- **The Limits of Sandboxing:** Altman expresses deep pessimism that static sandboxing is sufficient for a model a million times smarter than a security researcher, noting that safety ultimately relies on advanced activation monitoring, behavioral inspection, and rock-solid alignment.
- **Agent Teams vs. Swarms:** Rejecting the term "swarms" (which he likens to locusts), Altman advocates for "agent teams" operating in dynamic equilibria of push-and-pull, arguing that a trillion slightly superhuman AIs are vastly safer than a single monolithic superintelligence.
- **The Sales Pitch Challenge:** Altman acknowledges that the AI industry has done a poor job explaining to the public why the potential downsides and disruptions are worth the future industrial revolution, emphasizing that tools must empower individuals rather than concentrating all future decisions in San Francisco.

### Compute Economics, Scaling, and Chip Innovation
- **Test-Time Compute Expansion:** The ability to throw thousands of parallel test-time compute instances at a single problem has created a massive performance delta between advanced AI users and standard corporate implementations.
- **Internal Compute Allocation:** OpenAI grants researchers wide latitude to run massive compute experiments—such as spending order of magnitude $10 million on complex Navier-Stokes proofs—while actively pushing to decrease the cost per unit of intelligence.
- **Supply Chain Constraints:** Critical components like memory, DRAM, turbines, batteries, and concrete face severe supply constraints because memory manufacturers remain conservative with CapEx due to historical booms and busts.
- **Custom Silicon and Chip Design:** OpenAI is building its own chips and leveraging AI to handle complex chip design file generation for tape-out, a process well-suited for automated optimization.

### The Future of Commerce, Agents, and Web Forms
- **The Missing Macintosh Moment:** While personal agents (like Dots) are gaining traction, Altman notes the definitive mainstream "Macintosh moment" where users cannot imagine life without their agent has not quite arrived.
- **Agentic Commerce Defensibility:** Traditional businesses rely on HTML web forms and mobile apps for defensibility, but Altman argues this is transitory; true moats stem from brand loyalty and fulfillment networks (such as Amazon's logistics).
- **The End of Web Forms:** Altman asserts that filling out manual web forms and medical histories is "below human pay grade" and will inevitably be fully automated by personal agents.

### Predictions & Forward Calls
- **New System Architectures:** "I would bet that we have a completely new sort of model of how we make systems and networks." — Sam Altman
- **Cost Reduction Target:** Altman states that if the 5-year total cost of ownership to install and run a gigawatt of leading-edge AI does not drop significantly from current levels (around $70 billion toward a target of $20 billion), something has gone wrong in the supply chain.
- **OpEx Token Scaling:** Altman predicts that companies will soon routinely spend double-digit percentages of their operating expenses (10s of percentage points) on AI tokens.
